# 小程序点餐助手 · 离线演示

## 打开方式

用户端小程序代码位于独立小程序目录（可通过环境变量 `SKY_MINIPROGRAM_ROOT` 指定 `mp-weixin` 路径）。在微信开发者工具打开此项目目录后，从小程序「我的」顶部进入「点餐助手」。也可以在编译设置中把启动页面设为 `pages/customer-assistant/index`，直接看新页面，无需先走原小程序的业务流程。

- 点「帮我选餐」会填入「两个人，预算60元，不辣，帮我选餐」，可以改人数、预算和口味，再点发送。支持1至6人及不辣、微辣、辣三种演示口味。商品小计按分计算，不含配送和打包费；缺参数或预算不足时给出提示，不编造推荐。
- 点「查我的订单」再发送，显示该演示账号的两笔虚构订单，点卡片可看状态和商品明细。没有催单、支付、下单或取消按钮。
- 「新对话」只清除本页面中的演示记录，忽略旧请求的迟到结果；失败时保留问题，可手动重试。演示不读取登录凭证和真实订单，不调用模型或服务器。

## 文件分工

- `pages/customer-assistant/index.wxml` / `index.wxss`：暖黄色便当插画、快捷入口、对话与结果卡片、底部订单详情。插画由样式绘制，没有远程图片依赖。
- `pages/customer-assistant/demo.js`：虚构菜单、订单和有限的规则解析，不是大模型。无法核验过敏原、库存或实际费用。
- `pages/customer-assistant/controller.js`：输入、等待、错误、详情、新对话等页面状态；`index.js` 注册原生小程序页面。未修改现有登录、下单或支付逻辑。
- 现有小程序为编译后的 uni-app 目录。这次只在当前目录注册原生页面并加入口；若以后从其他 uni-app 源码重新构建，需要把该改动迁入对应源码，避免被覆盖。

## 离线验证

在 Agent 项目目录运行 `node --test tests/web/core.test.mjs tests/web/customer-mini.test.mjs`。测试默认引用本机小程序目录，其他机器可以设置 `SKY_MINIPROGRAM_ROOT` 指向自己的小程序目录。Node 测试验证交互状态和数据规则；微信开发者工具的本地编译器用于检查 WXML / WXSS。首次真实联调再为用户端接入已有聊天接口和用户身份，不能复用商家凭证。
