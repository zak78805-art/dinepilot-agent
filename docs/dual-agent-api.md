# 双端 Agent 接口与验证边界

本说明只描述已有代码契约，不表示接口已启动或已完成真实模型、Java与数据库联调。

## 路由和身份

| POST路径 | 身份 | 说明 |
| --- | --- | --- |
| `/api/agent/chat` | 管理员 | 旧网页兼容入口 |
| `/api/agent/merchant/chat` | 管理员 | 商家明确入口，9个只读工具 |
| `/api/agent/customer/chat` | 用户 | 用户入口，6个只读工具 |

商家使用`token`请求头或`Authorization: Bearer <管理员JWT>`，Java核验`/admin/agent/identity`。用户使用`authentication`或`Authorization: Bearer <用户JWT>`，Java核验`/user/agent/identity`。不要交换两端Token，也不要在URL、消息或日志中写Token。

## 请求

```json
{"session_id":"customer-demo-1","message":"两个人，商品预算60元，想吃不辣的，看看菜品和套餐。"}
```

message为1～4000字符，不能全为空格、换行、制表符等空白字符；非空问题不自动裁掉首尾空白。两端session_id统一为1～128位字母、数字、下划线或连字符；可以省略，由服务端生成。用户端额外字段会被拒绝，不支持role/user_id参数选权限。商家旧路径也使用相同校验：旧调用方若自定义了带空格、中文或超过128位的session_id，应改用合法新ID；原网页生成的UUID符合规则。

非法请求返回422，不进入Agent会话创建或模型调用；身份依赖仍可能先核验登录状态。这些校验不是完整限流、请求体大小保护或会话总量控制。

## 响应示例（仅契约示意，不是实测模型输出）

```json
{
  "agent_role":"customer",
  "session_id":"customer-demo-1",
  "answer":"这里是根据工具数据生成的回答。",
  "tool_calls":["get_customer_categories","get_customer_menu"],
  "approval_required":false,
  "approval_id":null
}
```

tool_calls仅表示本轮尝试调用的工具名称，不保证成功或返回了有效数据。没有购物车、下单、支付、取消或审批执行接口。商家与用户即使认证ID、会话ID相同，也使用不同实例及缓存键；同一个身份的同一会话串行执行。

## 错误

| 状态 | 常见原因 | 调用方处理 |
| --- | --- | --- |
| 401 | 缺令牌、格式错误、令牌过期或用错端 | 在对应端重新登录，不自动提升权限 |
| 403 | 认证主体已不存在或被禁用 | 联系管理员，不循环重试 |
| 422 | 用户端额外字段、两端会话编号错误、空白消息或过长 | 修正请求，勿自动重复发送 |
| 502 | 身份接口结构异常、工具/模型调用失败（含模型SDK认证、配额或供应商异常） | 提示暂不可用，人工检查；不要展示内部堆栈 |
| 503 | Java身份服务不可连接，或本端会话容量已满 | 根据detail检查后端，或清理本人闲置会话后手动重试 |

错误响应为`{"detail":"面向用户的说明"}`，422使用FastAPI标准结构化detail。工具执行遇到错误时也可能由Agent框架处理并给出文本回答；HTTP200不等于每个工具成功。当前未实现限流，不能宣称存在全局429保护。

模型供应商返回401不等于当前商家/用户登录过期；对外统一作为502助手调用失败，不透出供应商错误正文或密钥。Java身份核验返回401仍为登录身份错误，不混淆这两层。

## 安全与推荐边界

- 用户工具只允许固定GET路径；旧后端GET催单具有副作用，已明确排除。
- 订单由Java校验归属；Python再次校验每条userId并裁剪电话、地址等非必要字段。
- 推荐菜单按分类查询，可能被limit截断；不能称全店最优。口味不是过敏原证明。
- 商品价格及小计不包含未知打包/配送费，不承诺库存、最终实付或退款到账。
- 页面刷新会换会话ID；服务端采用有界内存会话，闲置回收与本人清空见下节；没有Redis持久化。
- 工具审计记录角色、认证主体ID、工具名、成功标记与耗时。参数默认不可信：仅保留经过类型/范围校验的有限查询元数据，手机号/订单号/凭证字段脱敏，未知字段不保存名称或内容；不保存返回正文或异常详情。查询本身不受脱敏影响。
- 当前只读审计为尽力记录：日志故障不改变工具结果或原异常；这不保证每次审计落盘。历史日志不自动追溯脱敏，也不自动删除。未来若增加写操作，必须另行设计可靠审计与审批，不沿用该故障策略作为合规保证。

## 可离线确认与不可离线确认

离线单元测试可确认请求映射、字段处理、权限拒绝、ContextVar隔离、工具注册和异常分支。生成的OpenAPI与工具清单来自实际代码，不依赖真实模型密钥。

离线测试不能证明模型选工具/推荐/算价的真实效果，也不能证明微信登录、数据库数据、网络路由与生产环境配置正确。所有模拟回答和虚拟Token仅用于测试，不能作为业务成功截图。

`tests/test_offline_scenarios.py`保留真实FastAPI路由、身份依赖、AgentScope执行循环、模型SDK适配、工具包装和业务客户端，只在两处HTTP边界使用MockTransport返回虚构响应。工具选择和最终文本是预先编排的，因此通过只证明执行与数据边界，不证明大模型理解了问题或能正确拒绝恶意指令。测试禁用重试以保持确定性，不改变生产重试配置。

## 聊天会话管理

`AGENT_SESSION_IDLE_SECONDS`默认1800，`AGENT_SESSION_MAX_ENTRIES`默认500，均为正整数。每端、每进程分别计数，合计默认最多1000个缓存条目，不是全局配额或内存字节限制；不影响JWT有效期。使用单调时钟，从最近一次请求结束计算闲置时间，后续聊天或清空请求触发清理；无请求时不会精确到点清理。

正在回答与排队的会话均不能回收。满额时新会话返回503，未过期的已有会话仍可使用；不会驱逐有效记录。模型HTTP客户端在移除空闲条目后尽力关闭，单次关闭等待上限2秒（要求关闭协程响应取消）；没有后台任务或Redis。

本人清空接口：

- `DELETE /api/agent/merchant/sessions/{session_id}`，使用管理员身份。
- `DELETE /api/agent/customer/sessions/{session_id}`，使用用户身份。

路径会话编号与聊天请求相同。服务端只使用认证主体与端类型，不使用查询参数里的user_id/role；不能清除其他主体同名记录。返回200：`{"agent_role":"customer","session_id":"demo","cleared":true}`。不存在、已过期或不属于本人的同名会话返回`cleared:false`，不暴露他人状态。活跃或排队时409，未登录401，编号不合法422。不会中断正在进行的回答。

清空后同ID重新聊天会创建新上下文；这不删除订单、审计日志或供应商可能保留的数据。商家网页「新会话」在确认后，通过同源代理调用商家DELETE接口；只有收到与当前会话匹配的成功响应才切换会话，失败则保留页面记录和草稿。过期也会丢失此前上下文，必要时请重新提供问题背景。
