# 本轮离线完善说明（2026-11-16）

## 1. 统一请求入口校验

`app/models/request.py`：商家、用户请求都限制session_id为1～128位字母、数字、下划线或连字符，拒绝只有空白的问题。非空问题保留原文，不进行自动改写。正常UUID及省略会话编号的请求继续可用；商家旧调用方若使用中文、空格或超长编号，需要换合法新ID。

根因是原先只有用户端限制会话编号，而两个请求模型的message最短长度只判断字符数，空格和换行也算字符。因此空白问题仍能创建Agent会话并消耗模型调用。

新增23项回归，先观察到14项失败，再修复后全部通过。无效请求不会进入Agent运行，但登录身份依赖仍可能先执行。会话编号限制不是Token有效期，JWT配置没有修改；也不代替会话容量、过期回收或请求限流。

## 2. 模型SDK异常转换

`app/api/routes.py`：商家和用户路由明确捕获已使用的模型SDK的OpenAIError，返回不含供应商内部详情的502提示。

原代码只捕获httpx和RuntimeError，真实SDK会把模型400/401/429/500等响应转换为自己的异常类，导致未处理500。使用真实SDK加MockTransport复现了两端8项失败，修复后通过。Java身份核验的401仍返回401，不把供应商API Key失效误报成当前用户登录失效。未改变生产重试、超时或模型配置，也没有新增依赖。

## 3. 离线业务场景回归

`tests/test_offline_scenarios.py`保留真实路由、身份核验、AgentScope执行循环、SDK格式转换、已注册工具、业务客户端与上下文管理，仅用内存HTTP模拟模型及Java响应；不启动HTTP监听、不使用真实数据。

18项覆盖商家今日统计、用户分类和菜单、本人订单列表与详情、他人订单拒绝、无权限工具拒绝、日期参数错误、SDK异常、同会话多轮、身份变化隔离及身份核验失败。模型选什么工具和最终回答什么由脚本指定，不代表模型自主推理或真实推荐质量。

调用测试可读作：虚构问题进入真实应用 → 脚本指定模型工具调用 → 真实工具处理模拟Java数据 → 检查实际送回模型的数据 → 返回脚本指定的最终文本。断言重点是数据与权限边界，不是“回答了脚本指定文本所以模型正确”。
