# 双端工具审计修复说明（2026-11-16）

## 问题和根因

商家与用户工具都经过`_run_tool`，原实现在finally中将arguments原样传给日志。手机号筛选等参数因而可能进入本地日志。日志初始化或写入若抛出异常，还会覆盖工具的正常返回值或正在传播的业务异常。

使用合成参数与内存日志复现：修复前新增测试出现4项失败，分别覆盖隐私参数、未知参数及日志失败覆盖成功/异常两个分支。没有读取真实日志内容、环境变量或密钥。

## 修改

- `app/audit.py`集中处理脱敏：只允许有限的查询字段，日期必须是合法ISO日期，数字有类型及范围限制，商品类型仅接受dish/setmeal。手机号、订单号及凭证字段只记脱敏标记；未知字段只记数量，连名称也不保存，避免字段名夹带隐私。
- `app/agent/merchant_agent.py`将原始日志调用替换为安全审计入口；用户端复用同一执行入口，因此同时生效。不改变工具输入、权限、返回值或接口Schema。
- 审计异常只尝试发出固定告警，不输出异常详情，不覆盖原工具结果。自定义文件处理器将写入故障交给这个安全入口处理，避免标准处理器将异常及文件路径打印到控制台。该真实文件处理器故障分支也经过先失败再通过的测试。未新增依赖，未修改Java、JWT密钥或令牌有效期。
- 复核发现通用logging告警若再次写入失败，可能打印原异常链；已用合成故障测试复现并修复。告警改为受保护的固定stderr文本输出，不再经过logging处理器；stderr不可用时也不改变原工具结果或异常。复核未发现本轮范围内剩余严重/重要问题。
- `tests/test_audit.py`使用虚构数据覆盖隐私、非法日期/数值、未知对象、成功/异常分支、用户角色与身份，以及审计初始化失败。

## 验证与限制

运行项目统一离线检查；禁止启动业务服务、浏览器或调用模型/数据库。本修复只影响后续工具审计，不重写、删除或自动脱敏已有日志。日志仍保留认证主体ID及有限主键，不能随意公开。

只读调用采用尽力审计，不保证落盘，也不包含日志丢失告警的持久化或可靠投递。未来写操作需要单独的审批和可靠审计设计。本轮不扩展写工具、持久化、限流或用户界面。

本轮统一离线检查通过：Python 136项（新增21项审计回归）、Node 18项、Java身份7项；接口契约导出及Python编译检查通过。80/8080/8090端口无业务服务监听。检查结果见`output/offline/summary.json`及Python JUnit报告；不代表真实模型回答质量或联调通过。
