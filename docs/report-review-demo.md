# 商家经营报告：写作 → 复核

要验证模型如何检查文字结论，参见[文字复核实验](report-text-review.md)。本页描述的是用规则校验数值的前一阶段。

这是独立离线实验。写作角色输出预设草稿，用来模拟商家 Agent 可能犯的错误；复核角色是本地规则，不是第二个模型。实验不改变现有商家和用户端，也不读取真实业务数据、凭证或环境配置。

在 `D:/sky-agent` 执行：

```powershell
.\.venv\Scripts\python.exe -m tools.report_review_demo
```

输出 JSON 包含证据（`evidence`）、未经复核的草稿（`draft`）、问题代码（`issues`）及复核后的结果（`reviewed`）。金额为分，完成率为万分比（5000 = 50.00%）。例如，固定样例中营业额是 158 元，4 单中完成 2 单：若草稿报成 176 元、75%，复核会按证据恢复为 158 元、50%，并将口径限定为「当前已完成订单」。

| 场景 | 草稿问题 | 如何复核 |
| --- | --- | --- |
| 正确草稿 | 无 | 原样通过 |
| 数字或口径错误 | 金额错误、完成率错误、误用全部已支付订单 | 验证期间、金额、分子分母与口径 |
| 零订单 | 把未定义完成率和未提供的取消数都写成 0 | 保持为空；区分「没有订单」与「没有这个字段」 |
| 原因缺证据 | 将未完成订单都算成取消单，进而归因于配送延迟 | 未提供的取消数保留为空；原因记未知 |

流程是「可信证据 → 写作角色 → 复核角色 → 最终检查」。复核后的内容仍不符合结构化证据时，流程拒绝交付。金额、计数、完成率和统计范围适合由代码检查，没必要交给另一个模型重算。以后若接真实复核 Agent，可以让模型复核**文字结论有没有超出证据**，结构化事实仍由代码把关。

固定样例共 4 个：预设草稿有 3 个故意带错，规则处理后这 4 个均符合检查条件。结果不代表真实模型正确率提升；本轮真实模型调用为 0，没有测真实延迟或 Token 消耗。规则不分析任意文本，也没有验证截图、配送数据或原因证明。真实评估应另准备未参与规则设计的报告题集，在同一批证据上对比单 Agent 与复核方案。
