# 商家报告文字复核 · 离线实验

结构化金额、完成率和统计口径仍由原有代码校验。本实验增加一个独立的文字复核角色，只判断草稿有没有把缺失信息、推测或局部样本写成事实。没有接入现有商家/用户 API，也不新增工具或业务写权限。

在 `D:/sky-agent` 直接运行：

```powershell
.\.venv\Scripts\python.exe -m tools.report_text_review_demo
```

## 复核交接

1. 调用方传入报告草稿与最小证据清单，每条证据有独立 ID。实验使用虚构聚合数据，不自行查数据库或订单。未来接入时，由调用方完成商家权限校验与脱敏。
2. 模型输出 `pass` 或 `revise`。退回时给出问题原句、原因、修改建议和证据 ID；正确且有明确限制说明的报告不应因措辞风格被退回。
3. 程序校验 JSON、原句是否确实出现在草稿中、证据引用是否存在。响应超时、模型错误、输出损坏时返回 `unavailable`，不同于通过。修改建议只供参考，不会自动发布或覆盖报告。引用存在也不保证模型解释正确。

适配器只使用调用方显式提供的模型客户端，没有默认凭证，也不会在脚本入口创建真实客户端。SDK 的请求格式已通过内存 HTTP 模拟验证，但没有测试实际模型供应商对 JSON 模式的支持。模型看不到商家或用户工具；证据与草稿作为数据放进用户消息。这样的处理不是对模型抗提示注入能力的实测。

## 对照题与结果

8 道题由固定证据人工标注：正确与应退回各 4 道，覆盖未完成不等于取消、榜单不是菜单、完成率下降不等于配送慢、零订单和营业额口径。结果分别记录漏判、误判、不可用和预期错误类型是否命中，超时不混入模型正确判断。

默认脚本预设 4 次通过、3 次退回、1 次超时。**这是控制流程的演示，不是模型效果成绩。** JSON 中 `elapsed_ms` 只表示本地模拟耗时，未消耗真实模型 Token。下一阶段需取得确认后，用固定证据与相同草稿运行真实对照，记录实现版本、误判漏判、模型耗时与 Token，再决定是否接入商家端。
